What happened?

  1. macOS says the app "cannot be verified" or "cannot be opened" → Section A
  2. Windows shows a SmartScreen blue screen → Section B
  3. VaultBasis starts but the workspace does not appear → Section C
  4. Receipt will not verify → Section D

A. macOS — security message on first launch

After ZIP extraction, if macOS Gatekeeper blocks the unsigned preview VaultBasis.app on first launch, that block is expected.

  1. Double-click VaultBasis.app in Finder. macOS will show a security dialog — click Done.
  2. Open System Settings → Privacy & Security and scroll down to the Security section.
  3. You will see a message that VaultBasis was blocked. Click Open Anyway.
  4. Enter your Mac password if asked. You only do this once.

After clicking Open Anyway, double-click VaultBasis.app again to open it. If it still fails to launch, stop and report the issue.

B. Windows — SmartScreen blue screen

After extracting the ZIP package, ensure you keep the package contents together (do not move VaultBasis.exe out of the extracted folder). When you launch VaultBasis.exe, Windows SmartScreen may block the preview.

  1. Click the underlined "More info" text.
  2. Click "Run anyway" at the bottom.
  3. Click Yes if Windows asks for permission.

You only do this once. If Windows still blocks it after these steps, stop and report the issue. Never disable Defender or SmartScreen globally.

C. VaultBasis starts but the workspace does not appear

If the local VaultBasis workspace does not appear immediately after launch:

  1. Wait a few seconds for the application to fully initialize.
  2. If it still does not appear, quit the application and relaunch it once.
  3. If the workspace is still unavailable after relaunch, stop and report the issue.

D. Receipt will not verify

  1. Use the included Offline Verifier included in your package. A verification of the original Outcome Receipt will display VALID.
  2. If the receipt is modified, it will display INVALID.
What the signature means — and does not mean: The signature proves the receipt content has not been altered since it was signed by your local installation key, under the verification scheme in the bundle. It does not by itself prove where the software was run, and it does not determine tax correctness, legal compliance, or whether source information is complete or factually accurate. Your reviewer makes the compliance determination.

Support: Reporting an Issue

If you remain blocked, stop and report the issue to your technical contact. Please include:

  1. Your operating system and version.
  2. Your system architecture (Apple Silicon, Intel, or Windows x64).
  3. The exact on-screen error message (screenshot if possible).
  4. The exact step you reached.
Important: Do not send taxpayer source files unless specifically requested through an approved support process.
Not supported in this preview: Intel Macs (untested), Linux desktop, iPadOS / iOS, Android, ChromeOS. The macOS preview binary is Apple Silicon (arm64) only.
