Product Assurance

Verifiable properties of the VaultBasis reconciliation and receipt system.

Deterministic Reconciliation

Reconciliation outcomes for the same source inputs are computed under fixed, published rules. Installation-specific elements — signing keys, timestamps, and receipt identifiers — are unique per installation.

View Evidence Contract ↗

Independent Receipt Verification

Outcome Receipts can be independently verified offline or via the hosted web verifier during preview. Verification operates entirely client-side without transmitting receipt contents to a server.

Open Web Verifier ↗

Local Evidence Boundary

Source evidence used in reconciliation is processed within the local VaultBasis Edge application. The website, access-request, and distribution interactions are a separate plane.

Scope & Limitations ↗

Cryptographic Signing

Outcome Receipts are signed using a locally generated Ed25519 installation key. Successful signature verification establishes that the receipt has not been changed since signing and that the signature matches the key declared in the receipt. It does not independently authenticate the originating installation.

Security

VaultBasis operates across three distinct planes. Each has a separate security boundary.

PlaneDescription
Local Edge The local VaultBasis Edge application processes source evidence, performs reconciliation, and generates the signed Outcome Receipt. Source evidence is processed within the declared local application boundary. See Scope & Limitations for tested network behaviour and known limitations.
Web / Marketing The public marketing website handles access-request submissions for provisioning purposes. It is a separate plane from the local Edge application. No reconciliation or evidence processing occurs here.
Distribution Qualified artifacts are recorded at build time with SHA-256 identities and stored in controlled storage before distribution. The distribution plane is separate from both the Edge application and the marketing website.

Privacy & Data Handling

How information is handled across each operational plane. See the Privacy Policy for full details.

  • Edge evidence processing Source evidence used in reconciliation is processed within the declared local application boundary. See Scope & Limitations for tested network behaviour and known limitations.
  • Website interactions The marketing website collects access-request information (name and email) for provisioning purposes. This information is used to review and provision design-partner access.
  • Receipt verification The Web Verifier performs verification in the browser using WebCrypto. Receipt contents are not sent to VaultBasis servers.
  • Contact and support Information submitted via contact or support routes is used to respond to the inquiry.

Enterprise IT Deployment & Security Profile

Information for Enterprise IT Administrators, CISO teams, and security reviewers evaluating VaultBasis on firm-managed endpoints.

Local Endpoint Architecture

VaultBasis binds strictly to 127.0.0.1 using standard user space privileges. Zero administrator/root elevation is required, and zero persistent background daemons are installed.

Zero Runtime Case Egress

Client transaction rows, Form 1099-DA imports, and tax-basis computations remain entirely on the local device. No taxpayer data or wallet information is ever transmitted to external servers.

Enterprise Durability

Local state is stored in SQLite using Write-Ahead Logging (WAL) with PRAGMA synchronous = FULL for enterprise-grade transactional resilience and crash recovery.

Governance

Specification, versioning, and change control for the VaultBasis evidence system.

  • Semantic specificationEvidence Contract v0.1 defines the receipt structure, outcome states, and signing algorithm. The specification is publicly available.
  • VersioningThe evidence contract is explicitly versioned. Changes require a version increment. Receipts declare their contract version so verifiers can apply the correct rules.
  • Release qualificationDistribution candidates undergo automated integrity, regression, and packaging checks before controlled release. Artifacts not passing qualification are not distributed.
  • Change controlChanges to the deterministic computation are evidence-controlled and tracked. The published specification and test vectors are updated with each version increment.
