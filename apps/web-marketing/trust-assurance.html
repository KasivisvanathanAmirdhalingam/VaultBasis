Product Assurance

Verifiable properties of the VaultBasis reconciliation and receipt system.

Deterministic Reconciliation

Outcomes are computed under fixed, published rules. The same inputs always produce the same output.

Independent Receipt Verification

Any reviewer can verify a signed receipt using the public Web Verifier without a VaultBasis account. Verification runs entirely in the browser.

Local Evidence Boundary

Source evidence used in reconciliation is processed within the local VaultBasis Edge application. The website, access-request, and distribution interactions are a separate plane.

Scope & Limitations ↗

Cryptographic Signing

Outcome Receipts are signed using a locally generated Ed25519 installation key. Successful signature verification establishes that the receipt has not been changed since signing and that the signature matches the key declared in the receipt. It does not independently authenticate the originating installation.

Security

VaultBasis operates across three distinct planes. Each has a separate security boundary.

Plane Description
Local Edge The local VaultBasis Edge application processes source evidence, performs reconciliation, and generates the signed Outcome Receipt. Source evidence does not leave this boundary during reconciliation or signing.
Web / Marketing The public marketing website handles access-request submissions for provisioning purposes. It is a separate plane from the local Edge application. No reconciliation or evidence processing occurs here.
Distribution Qualified artifacts are recorded at build time with SHA-256 identities and stored in controlled storage before distribution. The distribution plane is separate from both the Edge application and the marketing website.

Privacy & Data Handling

How information is handled across each operational plane. See the Privacy Policy for full details.

  • Edge evidence processing Source evidence is processed within the local Edge application boundary. Evidence does not leave the Edge application during reconciliation or signing.
  • Website interactions The marketing website collects access-request information (name and email) for provisioning purposes. This information is used to review and provision design-partner access.
  • Receipt verification The Web Verifier performs verification in the browser using WebCrypto. Receipt contents are not sent to VaultBasis servers.
  • Contact and support Information submitted via contact or support routes is used to respond to the inquiry.

Governance

Specification, versioning, and change control for the VaultBasis evidence system.

  • Semantic specification Evidence Contract v0.1 defines the receipt structure, outcome states, and signing algorithm. The specification is publicly available.
  • Versioning The evidence contract is explicitly versioned. Changes require a version increment. Receipts declare their contract version so verifiers can apply the correct rules.
  • Release qualification Candidate artifacts pass an automated multi-gate validation pipeline before promotion. Artifacts not passing qualification are not distributed.
  • Change control Changes to the deterministic computation are evidence-controlled and tracked. The published specification and test vectors are updated with each version increment.
