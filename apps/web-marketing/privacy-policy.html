Privacy Policy

Version: preview-v0.1  |  Effective: 2026-09-30  |  Design-Partner Preview Phase

Preview status. VaultBasis is in a controlled design-partner preview phase. This policy describes current practice for this phase. It will be updated before any general availability release. Counsel review is required before any commercial or regulated deployment.

Overview — Two Distinct Processing Planes

VaultBasis operates across two distinct planes. Understanding which plane applies to a given interaction is essential for reading this policy correctly.

  • Web plane — interactions with vaultbasis.com: visiting the website, submitting an access request, receiving a provisioning email, accessing support or disclosure routes. These interactions involve web infrastructure and are covered in Section 1.
  • Edge evidence plane — the local VaultBasis Edge application running on the practitioner's device: loading source files, performing reconciliation, generating and signing Outcome Receipts. These interactions occur locally and are covered in Section 2.

Local evidence processing does not mean that website interactions are local. The two planes are separate.

Section 1 — Web Plane

1.1 Website Hosting

The vaultbasis.com website is hosted on Vercel. Vercel may collect standard web server log data (IP address, request path, timestamp, browser user agent) as part of hosting operations. VaultBasis does not control Vercel's infrastructure-level logging. See Vercel's privacy documentation for details.

1.2 Design-Partner Access Requests

When you submit a design-partner access request, you provide your name and email address. This information is used solely to provision and communicate your design-partner entitlement. It is transmitted to a server-side function hosted on Vercel.

1.3 Entitlement Provisioning

When access is provisioned, an entitlement record is created in private server-side storage. This record contains your email address, an entitlement identifier, a hashed token, and an expiry timestamp. The raw bearer token is never stored — only its SHA-256 hash is retained. Entitlements expire 72 hours after creation.

1.4 Email Delivery

During the current design-partner preview phase, provisioning emails are routed through a mail delivery service. Your email address is transmitted to that service for the purpose of delivering your access link. Email delivery infrastructure operates as a web-plane subprocessor.

1.5 Support and Disclosure Interactions

If you contact VaultBasis via the general enquiries or security disclosure routes, any information you provide (name, email, description of the issue) will be used to respond to your enquiry and, where applicable, to address security concerns. Do not include taxpayer source files, CSV exports, or other sensitive financial evidence in support communications.

1.6 What the Web Plane Does Not Collect

VaultBasis does not operate advertising trackers, third-party analytics pixels, or marketing automation on vaultbasis.com during the preview phase. The website does not use cookies for tracking.

Section 2 — Edge Evidence Plane

2.1 Local Application Processing

The VaultBasis Edge application runs entirely on the practitioner's local device. Source evidence files (e.g., IRS Form 1099-DA CSV, Koinly CSV exports) are loaded and processed locally. Reconciliation computations occur within the local Edge process. No source evidence is transmitted to VaultBasis or any third party as part of reconciliation or signing.

2.2 Local Storage

Case data, reconciliation results, and Outcome Receipts are stored locally on the practitioner's device. VaultBasis Edge does not provide cloud backup, synchronization, or remote access to case data. The practitioner is responsible for maintaining and securing local storage.

2.3 Outcome Receipts

An Outcome Receipt is a signed local artifact. It is not transmitted to VaultBasis at creation. If a practitioner chooses to share an Outcome Receipt with a third party (e.g., for independent verification), that transmission is entirely the practitioner's decision and is outside VaultBasis's control.

2.4 Installation Key

VaultBasis Edge generates a local Ed25519 signing key on installation. This key is stored on the local device. It is used to sign Outcome Receipts. The public key is included in each signed receipt. VaultBasis does not hold, register, or have access to installation private keys.

2.5 No Telemetry in Preview

The current preview release does not include usage telemetry, crash reporting, or diagnostic data transmission. If this changes in a future release, this policy will be updated and design partners will be notified.

Section 3 — Data Retention

Access request information and entitlement records are retained for the duration of the design-partner preview phase and a reasonable period thereafter for accountability purposes. When the preview phase concludes, retention will be governed by the updated privacy policy in effect at that time.

Section 4 — Contact

For privacy enquiries, use the general enquiries route. For security concerns, use the security disclosure route. Do not include source evidence files or taxpayer financial information in any communication.

Section 5 — Changes to This Policy

This policy applies to the current design-partner preview phase only. It will be revised before any general availability release. The effective date above reflects when the current version took effect.
