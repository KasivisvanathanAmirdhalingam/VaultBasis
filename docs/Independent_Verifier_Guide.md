# VaultBasis Independent Verifier Guide

This guide explains how to independently verify a VaultBasis Outcome Receipt without requiring access to VaultBasis Edge or the original software that generated the receipt.

## What You Need
1. **The Receipt File**: A JSON file (e.g., `receipt-v0.1.json`) generated by VaultBasis.
2. **The Verifier Tool**: The `independent_verifier.html` file provided in the VaultBasis export bundle.
3. **Public Key**: The public key fingerprint or string provided by the VaultBasis installation (only required if cross-checking the exact installation identity).

## How to Verify (Offline)
The verifier runs entirely locally in your web browser. It does not require internet access, and no data is uploaded.

1. **Disconnect from the internet** (optional, but recommended to ensure absolute offline assurance).
2. Double-click `independent_verifier.html` to open it in your web browser (Chrome, Firefox, Safari, or Edge).
3. Click the **"Select Receipt JSON"** button and choose the receipt file.
4. The browser will use local WebCrypto to parse the JSON, reconstruct the canonical payload, and verify the cryptographic signature.

## Interpreting the Status

### ✅ Receipt Integrity: VALID
The receipt structure is intact and the canonicalization succeeded.

### ✅ Signature: VALID
The Ed25519 signature perfectly matches the canonical payload. This mathematically proves the data has not been tampered with since it was signed.

### ✅ Contract: COMPATIBLE
The receipt conforms to the supported `v0.1` Evidence Contract structure.

### 🔍 Declared Outcome
This displays the actual reconciliation finding (e.g., `MATCHED`, `BASIS_DIFFERENCE`, `UNRESOLVED_DATA`). 
*Note: A status of `UNRESOLVED_DATA` with a `VALID` signature means the receipt accurately and securely proves that the system could not resolve the facts. It does not mean the receipt is invalid.*

## Important Exclusions: What "VALID" Does NOT Mean
A `VALID` receipt verifies technical and cryptographic integrity. It **does NOT establish**:
* Tax correctness or IRS approval.
* The legal identity of the taxpayer.
* Whether the underlying CSV data uploaded to VaultBasis was truthful or accurate.
* Contemporaneous historical existence (it proves origin, not trusted time).

## Troubleshooting Errors
* **INVALID_SIGNATURE**: The JSON file has been tampered with. Even a single changed decimal point, space in a value, or altered timestamp will break the signature.
* **UNSUPPORTED_CONTRACT**: The receipt was generated using a newer or incompatible version of VaultBasis not supported by your offline verifier.
* **INVALID_SCHEMA**: The uploaded file is not a valid VaultBasis JSON receipt.
