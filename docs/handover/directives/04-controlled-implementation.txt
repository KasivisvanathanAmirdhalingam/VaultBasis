My assessment of the two newly confirmed defects
Focus escaping the Request Access dialog is a release blocker for the accessibility qualification. The modal needs a proper dialog lifecycle: focus enters it, remains within it while open, Escape closes it, the close control is keyboard-accessible, and focus returns to the exact triggering control. This belongs under MMP11-A11Y-001, not merely UI polish.
Unknown URLs returning the homepage with HTTP 200 is also a real defect. It creates a soft-404, masks broken navigation, weakens automated crawling, and makes it possible for bad links to appear functional. Unknown public routes should return the intentional 404 experience with the appropriate HTTP status. This should become a navigation/runtime qualification requirement, with negative tests such as /definitely-not-a-vaultbasis-route.
Neither requires touching the deterministic assurance kernel.
