The rule the new developer should remember
Development happens on bounded branches.
CI verifies the exact source.
Pre-production verifies the actual deployed experience.
Humans verify what automation cannot.
Release branches integrate only qualified changes.
Production receives a qualified candidate rather than becoming the test environment.
Production verification precedes main becoming the new accepted truth.
And above all:
A newer commit is not a better commit. A green commit is not necessarily a qualified commit. A deployed commit is not necessarily a production-verified commit. Qualification evidence determines promotion.

That should become the operating model for the new developer from this point onward.
